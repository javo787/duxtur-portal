# GEO: чтобы ИИ-ассистенты (ChatGPT, Gemini) находили и цитировали Duxtur

Короткая памятка: что известно, что уже сделано в коде, чем это измерять. Источники: официальные руководства Google и OpenAI, отраслевые исследования, обсуждения в сообществах (где это были единичные эксперименты, так и сказано).

## Что известно (и насколько надёжно)

- **Google** (AI Overviews / AI Mode / Gemini): официально это «всё ещё SEO». `llms.txt` и отдельная «ИИ-разметка» не нужны. Надёжно: это позиция самого Google.
- **ChatGPT**: чтобы страницу показали в поиске ChatGPT, её не должен блокировать `OAI-SearchBot`. Сам поиск, по публичным данным и исследованиям, опирается на индекс Bing; точные проценты в этих исследованиях разные, OpenAI их не подтверждает. Поэтому важны Bing Webmaster Tools и IndexNow (сделано, см. `SEO.md`).
- **Gemini** чаще цитирует сайты самих брендов, **ChatGPT** охотнее берёт сторонние справочники и каталоги. Поэтому нужны и сильные страницы на своём сайте, и присутствие на внешних площадках.
- **Локальные запросы** («клиника в Душанбе»): для Gemini решает Google Business Profile и карты, для обоих помогают одинаковые название, адрес и телефон на всех площадках.
- Единичный эксперимент из сообщества: рекомендации ChatGPT коррелировали с упоминаниями и ссылками, а не с «GEO-оценкой» страницы. Выборка маленькая, но совпадает с логикой выше.
- Искусственные упоминания и накрутка Google считаются спамом. Только настоящие упоминания, отзывы и партнёрства.

## Что уже есть в портале

SSR-страницы, `robots.txt` без блокировки ИИ-ботов, sitemap с hreflang, JSON-LD (MedicalClinic, Physician, MedicalWebPage, FAQPage, speakable, рецензент статьи), IndexNow + cron + подтверждение Bing. Импортированные клиники без описания закрыты `noindex` намеренно (тонкий контент, см. `clinic-seo.ts`); путь к индексу: владелец заявляет клинику и пишет описание.

## Что нельзя сделать кодом

Google Business Profile и Bing Places для клиник, упоминания в СМИ и каталогах, отзывы настоящих пациентов, описания клиник от самих клиник. Здесь работа руками.

## Замер: `npm run geo:audit`

Задаёт ChatGPT (OpenAI Responses API + `web_search`, примерное местоположение Душанбе) и Gemini (Google Search grounding) 25 вопросов из `scripts/geo-audit.prompts.json` на русском, таджикском и английском. Пишет, цитируется ли `duxtur.org`, названа ли Duxtur в тексте и какие сайты цитируются вместо неё.

```bash
npm run geo:audit -- --dry-run            # показать вопросы, ничего не отправляя
npm run geo:audit                         # оба движка, для которых есть ключ
npm run geo:audit -- --engines openai --lang ru --limit 5
```

- Ключи: `OPENAI_API_KEY`, `GEMINI_API_KEY` (в `.env.local`). Модели: `OPENAI_MODEL` (по умолчанию `gpt-4.1`), `GEMINI_MODEL` (по умолчанию `gemini-2.5-flash`); если модель снята с поддержки, ошибка API выводится как есть, поменяйте переменную.
- Один запуск: 25 платных вызовов на каждый движок. Отчёты: `reports/geo-audit/*.json` (все ответы и источники) и `*.md` (сводка); папка в `.gitignore`.
- Это вызовы API, а не приложения ChatGPT и Gemini: приложения добавляют персонализацию и память. Числа показывают тренд, а не место в выдаче. Запускать раз в 2 недели и сравнивать с первым замером.
- Таджикские формулировки составлены без носителя языка: стоит попросить носителя поправить их в `scripts/geo-audit.prompts.json`.
