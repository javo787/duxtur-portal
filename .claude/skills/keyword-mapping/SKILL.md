# Карта ключей Duxtur

Цель: решить, какой странице какой кластер запросов отдать. Это не просто группировка по словам.
Адаптировано из навыка keyword-clustering проекта OpenSEO (MIT, см. NOTICE.md). Платные API не нужны.

## Входные данные (что просить у владельца)

- Search Console → «Эффективность» → вкладки «Запросы» и «Страницы» → экспорт CSV. Лучше выгрузка по паре запрос+страница.
- Keyword Planner (Таджикистан, русский) → CSV. В малой нише объёмы диапазонами и округлены.
- Яндекс Вебмастер → «Поисковые запросы» → CSV. Только Google-данные в Search Console; Яндекс держать отдельным листом.
- Существующие URL: `src/app/sitemap.ts` или живой `https://www.duxtur.org/sitemap.xml`.

Если выгрузки нет, скажи, чего не хватает, и не строй карту «из головы». Карту по списку слов без данных помечай как черновик.

## Порядок работы

1. Собери ключи, убери дубли и нерелевантное (чужая специальность, чужой город, другой тип услуги).
2. Сгруппируй по интенту и типу страницы: список клиник, страница специальности, карточка клиники, карточка врача, статья.
3. Для каждого кластера выбери: существующий URL, новая страница или «ждёт данных».
4. Каннибализация: один запрос показывает несколько URL (по паре запрос+страница в Search Console). Для каждого случая назови, какой URL оставить.
5. Спорные пары проверь по живой выдаче через web_search. Результат из песочницы не из Таджикистана: помечай «не проверено в Таджикистане».

## Правила Duxtur

- Новая страница «тип/специальность + город» предлагается только если она пройдёт пороги индексации. Читай актуальные значения в `src/lib/clinic-seo.ts` (`MIN_INDEXABLE_LISTING_CLINICS`, `MIN_INDEXABLE_SPECIALTY_DOCTORS`, `MIN_INDEXABLE_DESCRIPTION_CHARS`, `listingIndexable`, `indexableListingFacets`), числа из этого файла не копируй в отчёт по памяти. Не проходит порог: статус «ждёт данных», страницу не создавать.
- Поиск (`?q=`) и сортировка не индексируются, ключи на них не мапить.
- Языки: ключи на ru. uz, tg, kk, ky публиковать только после проверки носителем; в карте помечай такие строки.
- Медицина (YMYL): запросы вида «лечение X» ведут на статью с автором-врачом, датой проверки и дисклеймером, не на коммерческую страницу. Никаких обещаний лечения и диагнозов.
- Не делай прогнозов трафика и позиций из объёмов. Объём это спрос, а не обещание.
- Меньше 10 пригодных ключей: простая карта без кластеров.

## Выход

Файл xlsx (навык xlsx), листы:
- «Кластеры»: кластер, главный ключ, интент, целевой URL, действие (создать / обновить / ждёт данных), язык, приоритет, эффект / трудоёмкость / риск.
- «Каннибализация»: запрос, URL-ы, какой оставить. Только при реальных данных.
- «Не брать»: что отброшено и почему.

В ответе (по-русски, с телефона): вывод в первой строке, потом список действий. Отдельно напиши, что проверено, а что нет.
