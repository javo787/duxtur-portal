# План реализации: Автоматизированная ИИ-система публикации медицинских статей (Auto-Blogger)

## 1. Концепция и бизнес-логика
Система автоматически, каждые 3 дня, находит самую актуальную и популярную медицинскую тему в англоязычном сегменте интернета, выбирает авторитетную статью, профессионально переводит её, адаптирует форматирование и публикует на платформе `duxtur.org`.

В конце каждой статьи автоматически добавляется подпись: *"Переведено командой duxtur.org. Источник: [ссылка]"*.

---

## 2. Как это делают другие (Опыт индустрии)
Ведущие контентные платформы и агрегаторы используют **многослойную ИИ-архитектуру (Multi-Agent System)**:
1. **Слой "Исследователь" (Trend Watcher)**: Не ищет "вслепую", а использует API поисковиков (Google Trends, NewsAPI) для выявления хайпа (трендов).
2. **Слой "Парсер" (Scraper)**: Извлекает чистый текст из HTML, отсекая рекламу и навигацию (используются инструменты типа Firecrawl, Jina AI или Browserless).
3. **Слой "Редактор-Переводчик" (Translator/Editor)**: LLM-модель с высоким контекстом, которой задают строгий системный промпт медицинского переводчика.
4. **Слой "SEO-оптимизатор"**: Та же модель генерирует мета-теги, keywords, красивый slug и JSON-LD.

---

## 3. Выбор ИИ-моделей и инструментов (Слои ИИ)

Для платформы `duxtur.org` (Next.js + Vercel) оптимален следующий стек:

| Слой / Задача | Рекомендуемый инструмент | Почему это лучший выбор |
| :--- | :--- | :--- |
| **Триггер (Расписание)** | **Vercel Cron Jobs** | Бесплатно, нативно интегрировано в Next.js. Настройка крона на каждые 3 дня. |
| **Поиск трендов и статей**| **Tavily API** / **SerpApi** (Google News) | Tavily создан специально для ИИ, возвращает чистый контент по поисковому запросу. |
| **Извлечение текста** | **Jina Reader API** (`r.jina.ai`) | Идеально превращает любую веб-страницу в чистый Markdown, понятный для LLM. |
| **Перевод и форматирование**| **Anthropic Claude 3.5 Sonnet** или **Gemini 1.5 Pro** | Claude 3.5 Sonnet лучше всех работает с форматированием Markdown и медицинским контекстом без "машинного" акцента. |
| **База данных** | **MongoDB** | Нативная БД проекта. Потребуется новая модель `Article`. |

## 4. Пошаговый алгоритм работы (Пайплайн)

1. **Инициация (День X, 03:00 ночи)**
   - Vercel Cron дергает защищенный endpoint: `POST /api/cron/generate-article`.
2. **Анализ трендов (AI Layer 1)**
   - Запрос к ИИ: *"Какие медицинские темы (новые исследования, советы по здоровью, эпидемиология) наиболее популярны на этой неделе на английском языке?"*
   - ИИ использует поисковый API (например, Tavily) и возвращает 1 конкретную тему.
3. **Поиск источника (AI Layer 2)**
   - Поиск качественной статьи по выбранной теме на авторитетных ресурсах (Healthline, Mayo Clinic, PubMed, Medical News Today).
   - Выбор URL лучшей статьи.
4. **Парсинг (Scraping)**
   - URL передается в `https://r.jina.ai/[URL]`, который возвращает статью в формате Markdown.
5. **Профессиональный перевод и верстка (AI Layer 3)**
   - Статья отправляется в Claude 3.5 Sonnet / Gemini с промптом:
     > "Ты профессиональный медицинский редактор и переводчик. Переведи эту статью на [ОДИН ИЗ ЯЗЫКОВ: RU, UZ, TG, KK, KY - можно настроить ротацию или переводить сразу на все]. Сохрани и улучши форматирование Markdown, сделай текст понятным для широкой аудитории, но сохрани медицинскую точность. Добавь структуру (H2, H3, списки). В конце ОБЯЗАТЕЛЬНО добавь: '*Переведено командой duxtur.org. Источник: [URL]*'."
   - Также ИИ генерирует: `title`, `SEO description`, `tags`, `cover_image_prompt` (для генерации картинки, если нужно).
6. **Сохранение в БД**
   - Создается запись в коллекции `articles`.
   - Регенерация статики Next.js (`revalidatePath`), чтобы статья сразу появилась на сайте.

## 5. Схема базы данных (Модель `Article`)

```typescript
// src/models/Article.ts
import mongoose from 'mongoose';
import { MultilingualString } from './types'; // Использование существующей структуры локализации

const ArticleSchema = new mongoose.Schema({
  title: { type: Object, required: true }, // Multilingual
  slug: { type: String, required: true, unique: true },
  content: { type: Object, required: true }, // Markdown контент (Multilingual)
  excerpt: { type: Object }, // Краткое описание для SEO
  coverImage: { type: String }, // Ссылка на картинку (Unsplash API или AI Generation)
  sourceUrl: { type: String, required: true },
  topic: { type: String },
  publishedAt: { type: Date, default: Date.now },
  status: { type: String, enum: ['draft', 'published'], default: 'published' }
}, { timestamps: true });
```

## 6. План разработки

* **Спринт 1: Подготовка инфраструктуры**
  * Создание модели `Article.ts` в MongoDB.
  * Разработка UI: Страница `/blog` (агрегатор статей) и `/blog/[slug]` (чтение статьи).
  * Настройка Markdown рендеринга (например, библиотеками `react-markdown` + `tailwindcss/typography`).

* **Спринт 2: Интеграция AI**
  * Написание сервиса `src/lib/ai-blogger.ts`.
  * Интеграция Tavily (для поиска статьи).
  * Интеграция Jina AI (для конвертации HTML в Markdown).
  * Интеграция LLM (OpenAI/Anthropic) для перевода и структурирования.

* **Спринт 3: Автоматизация**
  * Создание API-роута `/api/cron/ai-blog`.
  * Настройка `vercel.json` для вызова крона раз в 3 дня:
    ```json
    {
      "crons": [
        {
          "path": "/api/cron/ai-blog",
          "schedule": "0 3 */3 * *"
        }
      ]
    }
    ```
  * Тестирование пайплайна, добавление Sentry для отслеживания ошибок генерации.

## 7. Важные нюансы и риски (Как избежать проблем)

1. **Медицинский дисклеймер:** Перед футером с подписью ИИ должен автоматически вставлять блок: *"Информация носит ознакомительный характер и не заменяет консультацию врача."* Это юридически обезопасит проект.
2. **Галлюцинации перевода:** Использовать параметр `temperature: 0.1` или `0.2` в LLM, чтобы модель переводила строго по тексту и не придумывала факты.
3. **Авторские права:** Использовать статьи из открытых источников и новостных сайтов, не парсить платные медицинские журналы (Paywalls). Наличие обратной ссылки ("Источник: ...") в большинстве случаев покрывает требования Fair Use для новостного контента.
4. **Мультиязычность:** Поскольку `duxtur.org` поддерживает RU, UZ, TG, KK, KY, на этапе генерации можно попросить LLM выдать JSON с переводами сразу на **все** языки платформы. Это кратно увеличит SEO-трафик со всей Центральной Азии.
