## 1. Коротко

**Главный вывод:** код сайта в хорошем состоянии (canonical на `www`, hreflang, JSON-LD, robots.txt, динамический sitemap, тесты на SEO). Проблема не в коде, а в том, что **Google почти ничего не знает о сайте**:

- в Search Console **не отправлено ни одного sitemap**;
- все проверенные статьи и каталог клиник: **«URL is unknown to Google»** (Google ни разу их не видел);
- за 90 дней **весь трафик (104 из 104 кликов) пришёл на языковые главные**, и почти только по брендовым запросам (`duxtur`, `духтур`);
- в sitemap всего **8 адресов статей** из 213 URL; основная масса: клиники и их фильтры.

Поэтому порядок такой: **сначала открыть сайт для Google (индексация), потом наращивать полезный медицинский контент и доверие к нему, потом внешние сигналы.** Менять ключевые слова в заголовках без этого почти ничего не даст.

**Пять действий, которые дают больше всего за наименьшее время:**

| # | Действие | Время | Эффект |
|---|---|---|---|
| 1 | Отправить `https://www.duxtur.org/sitemap.xml` в Search Console | 5 минут | Google узнает о статьях, врачах, клиниках |
| 2 | Сделать редирект `duxtur.org → www.duxtur.org` постоянным (308 вместо 307) | 10 минут | Один основной хост, сигналы не делятся |
| 3 | Добавить страницы рубрик `/blog/c/*` и hreflang в sitemap | 1–2 часа | Рубрики и переводы находятся быстрее |
| 4 | Показывать врача-рецензента, а не только «Проверено врачом» | 0,5–1 день | Доверие к медицинскому контенту |
| 5 | Создать доменный ресурс `sc-domain:duxtur.org` в Search Console | 15 минут | Видны все хосты сразу, полнее данные |

## 5. Находки и решения

Приоритеты: **P0** блокирует рост, сделать в первую неделю; **P1** заметно влияет, 2–4 недели; **P2** усиливает, 1–3 месяца; **P3** долгосрочно.

### P0-1. Sitemap не отправлен в Search Console

- **Что:** `list_sitemaps` возвращает пустой список. Статьи и `/ru/clinics` «unknown to Google».
- **Почему важно:** sitemap для нового сайта с малым числом внешних ссылок — главный способ сообщить Google о страницах. Без него Google находит страницы только по ссылкам, а у статей их почти нет.
- **Что сделать:** Search Console → Sitemaps → `https://www.duxtur.org/sitemap.xml` → Отправить. Повторить в Bing Webmaster Tools (IndexNow там уже настроен).
- **Почему так:** файл уже генерируется и корректен, нужна только подача. Запросы «Request indexing» для каждой страницы руками не масштабируются, sitemap делает это для всех.
- **Проверка:** через 3–7 дней статус «Success», в отчёте «Страницы» растёт число проиндексированных.
- **Трудоёмкость:** 5 минут.

### P0-2. Временный редирект с `duxtur.org` на `www`

- **Что:** `https://duxtur.org/` → `307` → `https://www.duxtur.org/`. Редирект ставит Vercel (заголовок `server: Vercel`), а не middleware.
- **Почему важно:** 307/302 говорят «адрес временно в другом месте»: Google может держать в индексе оба хоста и делить сигналы. Внутренние данные это подтверждают: у страниц есть `referringUrls` вида `https://duxtur.org/ru/...` без `www`. Постоянный редирект (301/308) — сильный сигнал выбора основного адреса.
- **Что сделать:** Vercel → Project Settings → Domains → `duxtur.org` → Edit → Redirect to `www.duxtur.org`, тип **308 Permanent**. Если Vercel не даёт выбрать тип, сделать редирект в `src/middleware.ts` по аналогии с `*.vercel.app` (там уже есть такая ветка) с `status: 308`.
- **Почему `www`, а не наоборот:** все canonical, sitemap, OG-адреса и тесты уже на `www`, проиндексированные страницы выбраны Google на `www`. Менять основной хост — значит заново переносить сигналы.
- **Проверка:** `curl -sI https://duxtur.org/ru` → `308` и `location: https://www.duxtur.org/ru`.
- **Трудоёмкость:** 10 минут.

### P0-3. Нет доменного ресурса в Search Console

- **Что:** есть только `https://www.duxtur.org/` (URL-prefix). Данные по `duxtur.org` без `www` и `http://` в него не попадают.
- **Почему важно:** пока редирект временный, часть показов может уходить на другой хост, и мы их не видим.
- **Что сделать:** добавить ресурс «Домен» `duxtur.org` (подтверждение через DNS TXT у регистратора). Старый ресурс не удалять, история сохранится.
- **Трудоёмкость:** 15 минут + ожидание DNS.

### P1-1. Рубрики `/blog/c/*` и hreflang отсутствуют в sitemap

- **Что:** в `src/lib/sitemap-entries.ts` нет записей для `BLOG_CATEGORY_PAGES` (`cardiology`, `neurology`, `dentistry`, `pediatrics`, `dermatology`). Hreflang есть в HTML, но не в sitemap.
- **Почему важно:** рубрика — главная внутренняя ссылка на группу статей. `/ru/blog/c/dentistry` уже получает показы (30 за 90 дней) без sitemap. Hreflang в sitemap дублирует HTML и помогает Google быстрее связать переводы.
- **Что сделать:**
  1. Добавить `perLang('blog/c/<slug>')` для рубрик, в которых есть хотя бы одна статья (пустые рубрики не включать, они тонкие).
  2. Передавать `alternates.languages` в записи sitemap (Next.js `MetadataRoute.Sitemap` поддерживает это поле) только для языков, где перевод реально существует, по той же логике, что и в `blog/[slug]/page.tsx`.
  3. Тест в `sitemap-entries.test.ts`.
- **Трудоёмкость:** 1–2 часа.

### P1-2. Статьи плохо связаны ссылками

- **Что:** Google не знает даже про статьи, на которые есть ссылки с главной. Значит, Google просто редко обходит сайт: мало внешних ссылок, мало внутренних путей.
- **Почему важно:** частота обхода зависит от того, насколько сайт «востребован». Внутренние ссылки — бесплатный способ показать важность страниц.
- **Что сделать:**
  - блок «Читайте также» (2–4 статьи той же рубрики) в конце каждой статьи;
  - со страницы врача — список его статей и статей, которые он проверил;
  - со страниц клиник и специальностей `/doctors/<специальность>` — ссылки на статьи этой специальности, и наоборот;
  - ссылки в тексте статей на соседние темы (вручную редактором, без автоматической перелинковки по ключам).
- **Трудоёмкость:** 1–2 дня.

### P1-3. Медицинская проверка не прозрачна

- **Что:** статья о раке молочной железы: «Автор: Nuridinov Javokhir, **Студент**», рядом «Проверено врачом», но кто проверил — не указано. На главной заявлено «100% верификация авторов».
- **Почему важно:** медицина — тема YMYL («Your Money or Your Life»). Google в руководстве для асессоров требует для таких тем максимального доверия: понятно, кто автор, кто эксперт, на чём основан текст. Значок без имени — заявление без доказательства.
- **Что сделать:** см. [раздел 9](#9-доверие-к-медицинскому-контенту-e-e-a-t--ymyl). В JSON-LD уже есть `reviewedBy` и `lastReviewed`: нужно показать то же самое в видимой части страницы.
- **Трудоёмкость:** 0,5–1 день кода + работа редакции.

### P1-4. Дубль бренда в title главной

- **Что:** `Duxtur.org — Медицинские статьи от врачей Центральной Азии | Duxtur.org` (около 70 символов).
- **Почему важно:** длинный title Google обрезает или переписывает; повтор бренда тратит место, где мог быть смысл.
- **Что сделать:** для главной задать `title: { absolute: '...' }`, например «Duxtur.org — медицинские статьи от врачей Центральной Азии». Аналогично проверить другие языки.
- **Трудоёмкость:** 15 минут.

### P1-5. Адрес без слов у статьи о раке молочной железы

- **Что:** `/ru/blog/---------65481`. Уже отмечено в `SEO.md` как требующее решения владельца.
- **Почему важно:** слова в адресе — небольшой сигнал релевантности и, главное, понятны человеку в выдаче и в мессенджерах.
- **Решение:** сейчас статья **Google неизвестна**, значит, набранных позиций нет, и поменять адрес сейчас дешевле всего. Сделать slug `rak-molochnoy-zhelezy-faktory-riska-profilaktika-skrining-65481` и **обязательно** 308-редирект со старого адреса.
- **Трудоёмкость:** 30 минут.

### P1-6. Проверить тестовые и неполные профили

- **Что:** в sitemap есть `/ru/doctor/raj-kapur-1057`, а страница показывает «Зафар — Кардиолог». Похоже на тестовый или переименованный профиль.
- **Почему важно:** профили-заглушки в медицинском каталоге — тонкий контент и вопрос доверия.
- **Что сделать:** удалить тестовые профили или перевести их в `noindex`; при переименовании врача обновлять slug с редиректом.
- **Трудоёмкость:** 30 минут.

### P2-1. Пять языков без своего контента

- **Что:** `kk` и `ky` индексируются, но собственных статей на казахском и кыргызском нет; в Search Console по этим языкам ноль показов.
- **Почему важно:** интерфейс на казахском с русскими статьями внутри для Google — почти дубль русской версии. Это тратит бюджет обхода и размывает сигналы.
- **Решение (на выбор владельца):**
  - **A (рекомендуется):** сосредоточиться на `ru`, `tg`, `uz`, где есть аудитория (Таджикистан 98% кликов). Для `kk`/`ky` индексировать только страницы с реальным переводом, остальные закрыть `noindex` и убрать из sitemap и hreflang.
  - **B:** оставить всё как есть, если в ближайшие 3 месяца появятся авторы на казахском и кыргызском.
- **Трудоёмкость:** 0,5–1 день.

### P2-2. Core Web Vitals не измерены

- **Почему важно:** 75% трафика с мобильных, в регионе часто медленный мобильный интернет. Скорость влияет и на ранжирование (немного), и на то, дочитают ли статью (сильно).
- **Что сделать:** прогнать [PageSpeed Insights](https://pagespeed.web.dev/) для `/ru`, статьи, `/ru/clinics`, страницы врача (mobile). Цели: LCP < 2,5 с, INP < 200 мс, CLS < 0,1. Главная весит ~125 КБ HTML: проверить, не уходит ли в HTML лишнее.
- **Трудоёмкость:** 2 часа на замер, исправления по результатам.

### P2-3. Проверка структурированных данных

- **Что сделать:** прогнать статью, врача и клинику через [Rich Results Test](https://search.google.com/test/rich-results) и [Schema Markup Validator](https://validator.schema.org/); исправить ошибки и предупреждения.
- **Почему:** разметка уже богатая, и ошибка в одном общем модуле ломает её на всех страницах сразу.

| **3–4** | P1-2 внутренние ссылки; P1-3 видимый рецензент; страница редакционной политики | Разработчик + редакция | Статьи связаны, проверка прозрачна |
| **5–8** | Первый тематический кластер (раздел 8): 8–12 статей, ru + tg; P2-1 решение по kk/ky | Редакция + врачи | Первые небрендовые показы |
| **9–12** | Второй кластер; P2-2 исправления скорости; P2-3 разметка; 3–5 внешних упоминаний | Все | Отчёт за 3 месяца, сравнение с базовой линией |
| **13–26** | 2–3 статьи в неделю по кластерам; обновление старых; партнёрства (раздел 10) | Все | Устойчивый рост показов |

## 7. KPI: базовая линия и цели

Цели — **ориентиры**, а не обещания: результат зависит от числа и качества статей, конкуренции и обновлений Google. Сравнивать всегда одинаковые 90-дневные окна.

| KPI | Сейчас (4 авг – 1 ноя 2026) | Через 3 мес | Через 6 мес | Где смотреть |
|---|---:|---:|---:|---|
| Показы за 90 дней | 206 | 1 500–3 000 | 6 000–15 000 | Search Console → Эффективность |
| Клики за 90 дней | 104 | 200–400 | 500–1 200 | Там же |
| Доля небрендовых кликов | ~0% | 30%+ | 50%+ | Фильтр запросов «не содержит duxtur/духтур» |
| Запросов с показами | 4 раскрытых | 100+ | 400+ | Эффективность → Запросы |
| Статей с показами | 0 | 70%+ опубликованных | 85%+ | Эффективность → Страницы, фильтр `/blog/` |
| Статей в индексе | 0 из проверенных | 80%+ из sitemap | 90%+ | Отчёт «Страницы» |
| Sitemap в Search Console | 0 | 1, без ошибок | 1, без ошибок | Sitemaps |
| Опубликованных статей (ru+tg+uz) | ~8 | 30+ | 70+ | Админка |
| Статей с видимым рецензентом | 0% | 100% новых | 100% | Выборочная проверка |
| Core Web Vitals (mobile) | не измерено | все «Good» на шаблонах | все «Good» | PageSpeed / отчёт CWV |
| Средняя позиция | 2,9 (бренд) | упадёт до 10–20 | 8–15 | **Не цель:** падение нормально, когда появляются новые запросы |

> Почему средняя позиция «ухудшится»: сейчас сайт виден только по своему названию, где он первый. Когда статьи начнут показываться по запросам вроде «гипертония при беременности», первые позиции будут 20–50, и средняя вырастет. Смотреть нужно на показы и клики.

## 8. Контент-стратегия

### 8.1. Принцип: глубина в одной теме вместо охвата всех

Сейчас главная перечисляет много специальностей, но в большинстве рубрик 0–1 статья. Для Google сайт с 10 сильными связанными статьями по одной теме выглядит экспертнее, чем сайт с 30 разрозненными.

**Почему так:** Google оценивает не отдельные страницы, а то, насколько сайт в целом полезен и надёжен в теме. Тематический кластер (обзор + ответы на частные вопросы + перелинковка) показывает глубину.

### 8.2. Как выбрать первую тему

1. Есть реальный врач-эксперт, готовый проверять тексты (обязательно).
2. Есть спрос в регионе: проверить в Google Trends (Таджикистан, Узбекистан), подсказках Google, вопросах пациентов в Telegram-каналах и на приёме.
3. Есть локальная специфика, которой нет у Mayo Clinic и WebMD: цены, где сдать анализы в Душанбе, доступность препаратов, местные стандарты.

Уже есть задел: **гипертония** (2 статьи на tg), **GLP-1 / Оземпик** (ru, tg), **онкоскрининг** (рак молочной железы, гастроскопия, щитовидная железа).

### 8.3. Пример кластера «Артериальная гипертония»

| Тип | Пример темы | Зачем |
|---|---|---|
| Опорная статья | Гипертония: симптомы, диагностика, лечение | Собирает общие запросы, ссылается на все остальные |
| Вопрос пациента | Какое давление считается нормальным по возрасту | Частый простой вопрос |
| Вопрос пациента | Как правильно измерять давление дома | Практическая польза |
| Особая группа | Гипертония при беременности (есть на tg) | Перевести на ru |
| Неотложное | Гипертонический криз: что делать до приезда скорой (есть на tg) | Перевести на ru |
| Лекарства | Препараты от давления: группы и побочные эффекты | С обязательной оговоркой «не назначать себе самостоятельно» |
| Локальное | Где проверить сердце и давление в Душанбе | Ссылки на клиники и врачей портала |

### 8.4. Требования к каждой статье

- Отвечает на вопрос в первых 2–3 предложениях (так же чаще берут в AI Overviews, см. `GEO.md`).
- Автор с профилем; врач-рецензент с профилем, если автор не врач.
- Даты публикации и последнего медицинского пересмотра.
- Источники: клинические рекомендации, ВОЗ, профильные общества; не другие блоги.
- Ссылки на 2–4 связанные статьи и на врачей/клиники нужной специальности.
- Перевод делает или вычитывает носитель языка; машинный перевод без вычитки не публикуется.
- Пересмотр не реже раза в год.

### 8.5. Ритм

- Месяцы 1–2: 2 статьи в неделю (первый кластер полностью).
- Месяцы 3–6: 2–3 статьи в неделю + обновление старых.
- Лучше одна проверенная статья, чем три непроверенные.

## 9. Доверие к медицинскому контенту (E-E-A-T / YMYL)

**Почему это главный долгосрочный фактор:** для медицинских тем Google особенно строго оценивает, можно ли доверять источнику. Пользователь принимает решения о здоровье, поэтому малоизвестный сайт без видимой экспертизы ранжируется хуже, даже если текст хороший.

### Что показать на странице статьи

| Элемент | Сейчас | Нужно |
|---|---|---|
| Автор | Имя, «Студент» | Имя, роль, ссылка на профиль |
| Рецензент | «Проверено врачом» без имени | «Медицинская проверка: д-р Ф.И.О., кардиолог, стаж N лет» + ссылка на профиль |
| Даты | Публикация, «Обновлено» | + «Последний медицинский пересмотр: дата» |
| Источники | Есть (ВОЗ, Mayo Clinic) | Больше первичных источников и клинических рекомендаций |
| Политика | Есть `/editorial` | Ссылка на неё из каждой статьи; процесс исправления ошибок |
| Отказ от ответственности | Есть «обратитесь к специалисту» | Оставить |

### Что показать на профиле врача

- Фото, специальность, место работы, образование, стаж.
- Номер лицензии или документ, если это допустимо законом.
- Статьи, которые врач написал и которые проверил.

### Формулировки на главной

«100% верификация авторов» стоит заменить на то, что можно проверить: «Каждую статью проверяет практикующий врач: имя и специальность указаны в статье». Обещание, которое не подтверждается на странице, вредит доверию больше, чем его отсутствие.

## 10. Внешние сигналы и локальное SEO

Это нельзя сделать кодом (см. также `GEO.md`), но без этого рост ограничен.

| Действие | Почему | Приоритет |
|---|---|---|
| Профиль организации Duxtur в Google Business Profile (если есть юрлицо и адрес) | Брендовые запросы, карточка в поиске | P2 |
| Помочь клиникам-партнёрам завести Google Business Profile со ссылкой на их страницу на Duxtur | Локальные запросы «клиника в Душанбе» решаются картами | P2 |
| Одинаковые название, адрес, телефон клиник везде | Google сверяет данные между источниками | P2 |
| Партнёрства с медуниверситетами, ассоциациями врачей | Качественные тематические ссылки | P3 |
| Врачи-авторы ставят ссылку на свой профиль Duxtur в соцсетях | Естественные ссылки + подтверждение личности | P2 |
| Публикации в региональных СМИ (комментарии врачей портала) | Упоминания бренда и ссылки | P3 |
| Telegram-канал с анонсами статей | Основной канал региона, даёт прямой трафик и упоминания | P2 |

**Чего не делать:** покупать ссылки, обмен ссылками ради ссылок, каталоги-«помойки». Это нарушение правил Google, и для медицинского сайта последствия особенно болезненны.

## 12. Чего не делать

| Соблазн | Почему нет |
|---|---|
| Массово генерировать статьи ИИ без проверки врачом | Нарушение политики Google о масштабированном контенте; для медицины ещё и риск вреда |
| Набивать ключевые слова в title и текст | Не работает с 2010-х, ухудшает читаемость |
| Ставить FAQ-разметку на всё подряд | Уже правильно отключено (см. `SEO.md`): разметка без реальных вопросов-ответов вводит в заблуждение |
| Менять адреса проиндексированных страниц без 301/308 | Потеря набранных позиций |
| Каждый день нажимать «Запросить индексирование» | Есть лимит, не ускоряет; sitemap + ссылки работают лучше |
| Переводить все страницы на все 5 языков машинно | Тонкие дубли, плохой опыт для носителей |
| Ожидать результата через неделю | Новому сайту нужно 3–6 месяцев на заметный рост |

## 14. Приложение: команды проверки

```bash
# Редиректы: ожидается 308 на www
curl -sI https://duxtur.org/ru | grep -iE '^(HTTP|location)'
curl -sI http://www.duxtur.org/ru | grep -iE '^(HTTP|location)'

# Canonical и hreflang страницы
curl -s -A 'Googlebot' https://www.duxtur.org/ru/blog/c/dentistry \
  | grep -oE '<link rel="(canonical|alternate)"[^>]*>'

# Состав sitemap по разделам
curl -s https://www.duxtur.org/sitemap.xml | grep -o '<loc>[^<]*' \
  | sed 's/<loc>//' | awk -F/ '{print $5}' | sort | uniq -c

# Есть ли рубрики и hreflang в sitemap (после P1-1 должно быть > 0)
curl -s https://www.duxtur.org/sitemap.xml | grep -c 'blog/c/'
curl -s https://www.duxtur.org/sitemap.xml | grep -c 'xhtml:link'

# Robots
curl -s https://www.duxtur.org/robots.txt | tail -5

# Тесты SEO в коде
npx vitest run src/lib/sitemap-entries.test.ts src/lib/seo-consistency.test.ts src/lib/blog-seo.test.ts
```
